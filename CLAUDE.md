# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

`dde` (docker dev environment): one shared `docker-compose.yml` defining many versioned service containers (php-cli/php-fpm 5.6–8.5, mysql/mariadb/percona, apache/nginx, varnish, redis, rabbit, elastic/opensearch, solr, node, mailhog/mailpit, ...) plus a bash CLI (`bin/dde`) that projects use to start and exec into them. Projects opt in with a `.env.dde` file in their root (template: `.env.dde.sample`) listing `DOCKER_CONTAINER` (comma-separated) and `DEFAULT_CONTAINER`.

## Development commands

All tools run in pinned docker images via the `Makefile`; nothing needs to be installed locally (override with e.g. `make test BATS=bats`).

```bash
make check            # everything CI runs: check-generated, lint, check-compose, test
make generate         # regenerate bin/dde + bin/completions.bash from bin/src
make test             # bats suite (tests/*.bats)
make lint             # shellcheck (generated bin/dde) + hadolint (docker/*/Dockerfile)
make check-compose    # tools/check-compose.py: names, aliases, mounts, ports, .env.sample variables
docker run --rm -v "$PWD:/work" -w /work bats/bats:1.11.1 tests/cli.bats -f 'exec'   # single file / filter
```

- `check-generated` diffs the regenerated files against the git index, so `git add` your source changes before running `make check` locally.
- Tests never touch a real docker daemon: `tests/bin/docker` is put first on `PATH` and logs each call (`printf %q`) to `$DDE_TEST_LOG`; assert with `assert_docker_calls`. `tests/test_helper.bash` builds an isolated dde home + workspace per test.
- `tools/check-compose.py` resolves the model with `.env.sample` values and a fake `DOCKER_VOLUME_BASE_PATH=/dde-volume-base`; known alternative services allowed to share host ports are listed in `ALTERNATIVES`.
- CI: `.gitlab-ci.yml` (origin, one job per tool image, no docker-in-docker) and `.github/workflows/ci.yml` (github mirror, `make check` + bats on macOS).

## The CLI (`bin/dde`) is generated by bashly

- `bin/dde` is **generated** — do not edit it directly. Edit `bin/src/bashly.yml` (commands, args, flags, help) and `bin/src/*_command.sh` / `bin/src/lib/*.sh`, then regenerate:
  ```bash
  alias bashly='docker run --rm -it --user $(id -u):$(id -g) --volume "$PWD:/app" dannyben/bashly'
  bashly generate
  ```
- `bin/completions.bash` is generated by `completely` from the same definitions; regenerate it when flags/commands change.
- `bin/alt/` holds the legacy pre-bashly `dde-*` scripts; not used by `bin/dde`.

Flow of a command:
1. `bin/src/initialize.sh` runs first: sources the repo's `.env` (global settings: `DOCKER_COMPOSE_COMMAND`, `USER_ID`/`GROUP_ID`, `DOCKER_VOLUME_BASE_PATH`, host IPs/ports, `*_BASE` paths), then sources `$PWD/.env.dde` (falls back to `$PWD/.env`) for project settings. It defines `parse_command_args`, which builds the docker compose argument arrays (`MODEPART` exec vs `run --rm`, `USERPART`, `TTYPART`, `WORKINGDIRPART`, `SERVICE`, `CONTAINER_LIST`).
2. Each `*_command.sh` calls `parse_command_args` and runs `${DOCKER_COMPOSE_COMMAND} -f "${DOCKER_DEV_ENVIRONMENT_HOME}/docker-compose.yml" ...`.

Details that matter when changing behavior:
- Working dir default: `PROJECT_ROOT` from `.env.dde` if set, else `$PWD` relative to the resolved `vhosts` symlink, mapped to `/var/www/vhosts/<rel>` inside the container. `-d` drops `-w` entirely (needed for containers that don't mount `vhosts`, e.g. db/redis/elastic).
- Backward-compat vars still honored: `PHP_CLI_CONTAINER` (overrides `DEFAULT_CONTAINER`) and `PHP_FPM_CONTAINER` (appended to `DOCKER_CONTAINER`).
- `dde start` calls `touchConfigFile` (`bin/src/lib/build.sh`) per container before `up -d`: on first start it copies sample config into place (php: `config/<svc>/sample/conf.d/*.ini` + `php.ini.sample`; nginx: `default.conf`; varnish: `default.vcl`) or touches an empty config (mysql-family `my.cnf`, ssh `tunnel.conf`) so the bind mount source exists.
- `dde init` writes `~/.docker/.dderc` (exports `DOCKER_DEV_ENVIRONMENT_HOME`, adds `bin/` to `PATH`, sources completions) and appends a `source` line to `~/.bashrc` / `~/.zshrc`.

## docker-compose.yml conventions

- Every service has `container_name` = service name = network alias on the single `app-tier` bridge network; containers reach each other by service name.
- Image sources live in `docker/<service>/Dockerfile`; builds receive `USER_ID`/`GROUP_ID` args so files are owned by the host user. PHP CLI containers run as `$USER_ID:$GROUP_ID` with home `/home/phpcli`.
- Volumes are **named volumes with local bind `driver_opts`** pointing at `${DOCKER_VOLUME_BASE_PATH}/config/<service>/...` or `${DOCKER_VOLUME_BASE_PATH}/data/<service>`. `vhosts` binds `${DOCKER_VOLUME_BASE_PATH}/vhosts` (a gitignored symlink to the user's projects dir) to `/var/www/vhosts`.
- Adding a new service version typically means: a `docker/<svc>/Dockerfile`, a service block, its named volumes in the top-level `volumes:` section, a `config/<svc>/` tree (runtime files gitignored, `sample/` committed), and a unique host port (pattern e.g. mysql `33NN`, php-cli `444NN`). Copy the nearest existing version and adjust — the blocks are near-identical.
- Shared env files for services are in `env/` (e.g. `env/db.env`).
- Only some containers mount `vhosts` (web servers, php-*, node-*, ssh, python, solr, tomcat, selenium-side-runner); infrastructure containers do not.

## Config layout

- `config/<service>/sample/` is committed; the live config next to it (`etc/`, `bin/`, `local/`, ...) is user-local and gitignored.
- Apache: `config/apache-24/conf.d/00_httpd.conf` and `01_macro.conf` (per-PHP-version `Use PHPxx "<docroot>"` macros, plus `Use SSL ca <name>`); per-project vhost `.conf` files go alongside and are gitignored. A vhost file needs a trailing newline after the last `</VirtualHost>`.
- SSL certs: generated inside the apache container with `ca-gen` / `cert-gen` into `conf.d/ssl/{key,csr,crt}` (see README).
- PHP extensions/xdebug are toggled via `config/php-(cli|fpm)-NN/etc/php/php.ini` and `conf.d/*.ini`; `config/php-cli-NN/bin` is mounted as `/home/phpcli/bin` (first on PATH).
- Extra Solr libs: `lib/solr/<version>`.
